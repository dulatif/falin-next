# Next.js DevTools MCP Use Cases

This document outlines how the **Next.js DevTools MCP** server enhances the AI assistant's ability to help with the development, debugging, and optimization of this project.

## 1. Runtime-Aware Debugging
Unlike standard static code analysis, the MCP allows the agent to see the **live state** of the application.
- **`get_errors`**: Retrieves real-time build errors, runtime exceptions, and hydration mismatches directly from the Next.js dev server.
- **Source Mapping**: AI can trace errors back to exact source lines using source-mapped stack traces provided by the runtime.
- **Log Streaming**: Access to `get_logs` allows the agent to read development server output without manual copy-pasting.

## 2. Structural Exploration
Quickly understand the scope and architecture of the running application.
- **`get_routes`**: Scans the filesystem to list all App Router and Pages Router entry points, including dynamic segments like `[id]` or `[...slug]`.
- **`get_project_metadata`**: Confirms environment details like the project path and local development URL.

## 3. Page & Component Inspection
Understand what's happening on a specific page currently open in the browser.
- **`get_page_metadata`**: Identifies which components, server actions, and data sources contribute to the current render.
- **`get_server_action_by_id`**: Traces specific Server Action IDs back to their function definitions in the source code.

## 4. Accelerated Migrations (Next.js 16+)
Leverage automated tools for modernizing the codebase.
- **`upgrade_nextjs_16`**: Guides through the upgrade process using official codemods to handle breaking changes in async APIs (Params, Cookies, Headers).
- **`enable_cache_components`**: Automates the transition to "Cache Components" mode, helping implement `"use cache"` and Suspense boundaries.

## 5. Automated Verification
Verify fixes and features in a real environment.
- **Browser Automation**: Integrated Playwright support allows the agent to "smoke test" routes by navigating, clicking, and checking for console errors.
- **Fast Feedback Loop**: The agent can apply a fix, trigger a refresh, and immediately verify if the error state has cleared using `get_errors`.
